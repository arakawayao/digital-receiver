# 简易数字接收机

本项目对应 2026 年秋季“工程教育（高级）”课程的简易数字接收机课题。目标是基于软件无线电架构，用 FPGA 完成信号采集、数字下变频和预处理后的数据传输，在上位机完成 AM/FM 识别、解调、实时放音及测量结果管理，并完成相关电路和结构设计。

## 系统职责

当前设计方向及功能分工如下，器件和具体实现参数待定：

```text
SMA 输入单个 88 MHz 至 108 MHz AM/FM 信号
    -> 射频预选滤波/驱动 -> AD9235 或 ADC12020（带通采样，不设模拟混频）
    -> FPGA：并行采集 -> 别名频率数字下变频 -> 滤波/抽取、方向校正 -> 帧封装
    -> USB 3.0 桥接与数据传输
    -> 上位机：AM/FM 识别与解调 -> 实时音频输出
              中心频率等参数测量 -> 测量结果管理
```

当前不要求同时接收整个 20 MHz 频段。带通采样需让单个信号的完整边带避开折叠边界；固定 20 MS/s 对 100 MHz 中心信号存在边带重叠，不能作为全范围通用配置。未知 RF 中心频率还需多采样率或其他信息消歧，单次 FFT 的别名频率不是唯一 RF 测量结果。19/20 MS/s 仅为模型档位示例，前端、时钟和性能均需验证。

## 开发与运行

目前没有可直接运行的接收机应用。离线 harness 使用 Python 3.11 或更新版本，仅依赖标准库，无需安装 PyTorch。不要以运行 `test.py` 作为项目功能验收。

在项目根目录执行：

```powershell
python -B -m harness.runner list
python -B -m harness.dialog
python -B -m harness.runner run --jobs 3
python -B -m harness.runner run --jobs 2 --task generate-fixtures
```

`--task` 可重复指定，自动包含所需依赖。运行器执行任务清单中的本地命令，不会启动新的 AI 会话。无前置依赖的检查可并行运行，样本生成等待 IQ 契约和信号测试成功；失败会阻止依赖任务，同时保留无关任务的执行结果。

日志和每次运行的 `summary.json` 保存至 `.harness/runs/` 下的独立目录，合成数据保存至 `.harness/fixtures/`。退出码 0 表示所选任务全部通过，1 表示运行失败或被依赖阻塞，2 表示参数或配置错误，130 表示用户中断。文件归属声明用于提前检查写入冲突，不是安全沙箱。

每个项目同时允许一个 harness 运行，由该运行内部的 `--jobs` 控制并发，避免两个调度器同时覆盖共享样本。`--output-dir` 只能指向项目 `.harness/` 下的子目录。异常断电或强制结束调度器可能留下 `.harness/run.lock`；先确认旧调度器及其子进程均已结束，再删除空锁目录恢复运行，不要在运行期间清锁。

并行工作包及交付门槛见 `docs/work_plan.md`，IQ 格式和测试参数见 `docs/iq_contract.md`。离线 JSON 格式只是模块协作基线，不是已确定的 FPGA 硬件传输协议。

后续 harness 工作先读取工程设计说明第 10 节，按两款候选及速率等级配置采样上限、实际时钟和码型，补充带通采样、折叠边界、RF 消歧、方向校正及 12 bit 转换测试。上述检查尚未实现或注册，本次文档更新不改变已有 harness 和离线 IQ 契约。

建立实际工程时，应在对应目录说明工具版本、依赖、入口、构建或仿真步骤、测试数据和结果位置，并同步更新本节。开发前阅读 `AGENTS.md`，遵循全局及项目级规范。

建议按以下顺序推进：

1. 补齐课程规范和验收指标，完成器件与采样方案论证。
2. 定义采样率、数据格式、处理链路和传输协议，建立 AM/FM 算法参考模型。
3. 实现并验证 FPGA 采集、数字下变频、预处理和传输模块。
