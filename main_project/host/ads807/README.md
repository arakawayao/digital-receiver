# ADS807 上位机

本目录源码位于独立host工程内，建议先读 [工程入口](../README.md)。

本应用现对应 `main_project/fpga/receiver_ads807_dual`，使用 Python 3.11 / PyQt6。
启动时不自动连接 USB，音频默认关闭。合成数据源始终明确标记，不能作为上板结果。
旧 `receiver_ads807` 的 FCR1 v2 文件仍可回放；USB 实时连接使用EP4CE6两模式TCM1/TRI1固件。

下述为2026-10-20较早的独立ROM实板流程，依赖历史三模式测试固件，
不作为当前两模式ADC工程的验证或启动入口；本次未运行，也未修改其烧录行为。
历史 `python -B -m ads807.board_test --offscreen --seconds 30` 实板测试入口，
显示 EP4CE6 三种模式、大/小幅度 AM/FM 的实际 USB 数据，并保留页面。
该入口也可为原自主回放工程使用 RPL1 上传与停止，不向其发送 TRI1 命令；普通 GUI USB 入口仍默认 TRI1。
构建前提、自动烧录行为、参数与未完成结果见
[FPGA联调说明](../docs/FPGA_INTEGRATION.md)。

## 启动

在 `D:\class_project\main_project\host` 执行：

```powershell
& 'D:\conda_envs\ads807_host\python.exe' -B -m ads807
```

也可在任意工作目录执行 `D:\class_project\main_project\host\run.py`，使用自己的 Python 解释器。
PowerShell 启动器使用当前环境的 Python 并切换到 host 工程目录。

不连接硬件的 AM 演示及右侧实时镜像：

```powershell
& 'D:\conda_envs\ads807_host\python.exe' -B -m ads807 --demo AM --preview
```

控制台输出本地预览地址，默认 `http://127.0.0.1:8767`；占用时选择后续空闲端口。
预览显示真实 Qt 窗口，提供三种视图切换和原尺寸查看；完整交互在桌面窗口中进行。
预览只绑定 loopback，不向外网提供服务。关闭应用后预览结束。
只需在浏览器中观察效果时，可增加 `--offscreen`；在高 DPI Windows 环境下，
该方式能减少截图引起的绘图负担。USB 性能验收应关闭镜像并独立实测。

依赖版本见本目录 `requirements.txt`。在已创建的环境中使用 `python -m pip check` 检查依赖。
不需要 PyTorch、浏览器服务器框架或替换 USB 驱动。

普通 GUI 的 USB 采集默认使用异步接收组件；首次使用或修改组件源码/SDK 后，先执行
`python -B -m ads807.build_usb_pump`，使用已安装的 .NET Framework C# 编译器和官方
CyUSB SDK 生成可追踪的接收组件；不增加 Python 包、不替换驱动。
TRI1 使用 128 个异步 512 字节 IN 请求和有界 32 KiB 批处理队列，独立 OUT 线程发送命令；
RPL1 先同步上传 RAM，在 START 前启用异步 IN；START 应答批次内的 I/Q 保存在有界 64 KiB
缓存并交给正常处理入口。组件缺失或哈希不一致时明确报错，不自动回退到同步读。
组件产物在host的 `.harness/ads807_host/managed/`，复制源码到新机器后需重新构建。
历史 `board_test` 入口仍通过 `--managed-pump` 显式选择该组件。
程序接口 `SourceConfig.usb_managed_pump=False` 保留同步诊断，普通 GUI 使用异步接收。

TRI1 控制与 DSP 分开：独立接收路由负责解包、CRC及全局序号校验，并立即分发 ACK；
DSP 从最多512批次的队列取数据。常规32 KiB批次约14.2 ms I/Q，512批约4.6 s，
满队列丢弃新批次并计数，在随后成功入队的 I/Q 上标记间断，不能拼成连续音频。
处理线程约每 40 ms 合并一批 I/Q，再按最多 10 Hz 更新识别和频谱，减少 Python/绘图调度开销。
“主机丢弃”合并原始接收队列及 DSP 队列的丢字节数；界面和保存统计另含 DSP 队列深度、丢样数及来源。
停止或 DSP 异常时继续解包，等待 STOP ACK 后关闭 USB；超时仍报告停止未确认。
手动配置会核对 ACK 回读的载频、NCO 步进与调谐使能；版本拒绝提示核对 TCM1 v2 SOF。
诊断参数 `--profile-processing <path>` 在停止后保存处理线程的 cProfile 证据；
采集期间不应同时运行综合、仿真或大型离线测试来干扰持续接收测量。
处理入口按整批转换 I/Q，连续样本仍全部进入音频解调；识别稳定后参数测量和 FFT 最多 10 Hz。
首次识别/类别切换仍逐块确认三次，削顶强制立即测量，连续性异常复位测量状态。
这降低了重复测量负载，不改变 USB 采样率、抽取配置、音频块或完整性判定。

## 界面与采集

- USB：配置 VID/PID（默认 04B4:1004）及调谐模式，点击开始。使用已有 Cypress 驱动和官方
  `CyUSB.dll`，可手动选择 DLL。EP2 IN=0x82 接收，EP6 OUT=0x06 发送 TCM1 命令；
  不发送 Vendor 命令、不刷固件或下载 SOF。FX2 需提供与新 FPGA 对齐的双向端点配置。
- 可选合成 AM、FM、无信号、噪声，以及保存的 `transport.fcr` / TRI1 / FCR1 原始文件回放。
- 默认自动显示解调波形，标签可切换 FFT 和原始 I/Q。鼠标滚轮缩放、拖动平移；手动缩放
  后暂停坐标跟随，数据仍持续更新。时间窗口为 2–200 ms；复位视图恢复跟随。
- 冻结显示只停止显示刷新，不停止接收或音频；保存取得后台最新连续段，最长约 2 秒，
  不一定是冻结画面中的数据。停止采集后保留最后的连续缓存。
- FFT 可选 2048/4096/8192 点，Hann 窗，显示数字本振相对频率及幅度 dBFS，
  分辨率分别约 244.14/122.07/61.04 Hz。频谱不是同时接收 88–108 MHz 全频段。
- 音频设备刷新、选择输出设备并勾选扬声器。单声道 48 kHz，默认音量 35%，FM 去加重
  可选关闭/50/75/100/150/200/300 µs。50/75 µs 是广播常用值，更长档位用于实验，
  可能使高频衰减更明显。更换设备前先关闭音频；系统默认设备可能是耳机。
- 保存会创建独立时间目录，含 `waveforms.npz`、`iq.csv`、`demodulated.wav`、
  `transport.fcr`、`metadata.json`。记录页可按时间、调制、载频或来源搜索；双击记录
  选择其原始帧文件，停止当前采集后点击开始回放。

## 两种调谐模式

| 模式 | 行为 |
| --- | --- |
| FPGA 自动估频（默认，1） | FPGA 过零估频调谐；上位机接收并解调，不发送 TUNE、TRACK 或 QUALITY |
| 手动载频（2） | 输入 88–108 MHz（6 位小数，即 1 Hz）；TUNE 后只报告质量，保持用户指定频道 |

两种模式不自动互换。模式、手动载频、失信保持时间在开始前选择；运行中停止后再修改。
默认失信保持500ms（1–60000ms），超时只标记状态，两种模式均保持已获得的调谐参数。
上位机自动搜索已删除；不发送SNAPSHOT/TRACK，不配置原始ADC快照RAM。
低可信度本身不复位 DDC、不清 FPGA FIFO，也不切断主机 I/Q 处理。
无有效调制时识别结果仍可为未知或无有效信号，不能将“已调谐”视为有效音频保证。
界面分开显示调谐设定、可信度、保持超时以及 Epoch / 配置编号。

每次连接先 QUERY → MODE → HOLD，手动模式随后 TUNE；停止时等待 STOP ACK 后结束接收。
2026-10-26 起，启动日志标记 `启动检查 v2026-10-26` 并显示本次手动载频。
信号源改频不会自动改变手动模式的接收频道，需在停止后同步修改上位机载频。
自动模式每约 0.5 秒只读 QUERY，即使没有 I/Q 也显示 FPGA 是否获得调谐参数；
启动超过 2 秒仍未收到 I/Q 时记录一次诊断。QUERY 不重新调谐、不清缓存。
停止改频后需先退出 AM 才能恢复的问题已提供 FPGA 候选修复，尚待烧录和真实硬件复测，见
[重启与 AM 锁频诊断](../docs/AM_RESTART_DIAGNOSIS.md)。
命令被拒绝、ACK 超时或控制事件溢出会报告错误并停止；不盲目重发、不自动断连重连。
命令序号从随机 u32 起点递增，降低重连时旧 ACK 被误匹配的可能。
质量阈值是原型参数，弱信号及复杂多载波性能仍需实测；QUALITY不会修改FPGA载频。

## 输入契约

依据：[接口协议](../docs/PROTOCOL.md)；对应FPGA实现为 `rx_tri_packet.v`、`rx_control.v`。
TCM1/TRI1编解码和IQ质量检查现统一维护于 `interfaces/protocol.py`、`interfaces/quality.py`。
FPGA旧Python路径只做兼容转发，应用无需外层工程目录。

| 项目 | TRI1 当前输入 |
| --- | --- |
| 帧 | 固定 512 B，小端，前 508 B 的 CRC32/IEEE 存在末尾；64 B 头，444 B 载荷 |
| 类型 | I/Q=1，每帧最多111对I16/Q16；ACK=3，48B应答；RAW=2仅兼容历史回放 |
| 采样率 | ADC=43,500,000 Hz；I/Q=500,000 Hz；CIC_SHIFT=40 |
| 频率 | tuned_rf 是设置值，estimated_rf 是测量；实际 LO 根据 phase_step 换算 |
| 连续性 | 所有类型共用全局序号；I/Q 单独检查 epoch、config_id、sample_index，不能将插入 RAW/ACK 误判为 I/Q 丢帧 |
| flags | bits1:0 模式；bit8 已调谐、9 可信、10 保持超时、11 削顶、12 暂态、13 累计溢出 |
| 方向及标度 | I=x*cos、Q=-x*sin，I+jQ、不共轭；signed16 / 32768，不代表电压或功率 |

当前实时USB若收到RAW则报告固件不匹配；历史RAW文件可解析，不用于当前调谐。
TRI1 中有暂态标志的整帧不进入解调和质量估计（保守丢弃，可能超过实际 66 对暂态）。
FPGA自动模式内部小幅调谐保留相位与滤波历史；主机在config_id变化时切分连续段，重新稳定音频。
短时可信度变化不切段；CRC / 帧序号 / I/Q 索引异常可观察，恢复后重新建立连续段。

旧文件回放契约如下；合成源继续使用此格式，不伪造硬件调谐结果。

| 项目 | 当前支持 |
| --- | --- |
| 帧 | FCR1 v2，512 B，前 508 B 的 CRC32/IEEE 存在末尾，小端 |
| 头 | 60 B；sequence、epoch、first sample index、count、累计 dropped 等 u32 |
| 数据 | 最多 112 对 I16/Q16，I 在前；未使用载荷应为 0 |
| 采样率 | 帧内读取并校验 ADC=43,500,000 Hz、I/Q=500,000 Hz |
| 方向 | `I+jQ`，FPGA 已采用 `I=x*cos, Q=-x*sin`，本工程 flags.bit1=0；不额外共轭 |
| flags | bit0 累计丢样，bit1 共轭，bit2 削顶，bit3 起始暂态，bit4 流格式标志 |
| 标度 | 头 offset48 的 CIC_SHIFT=40；IQ 以 signed16/32768 转换，不能视为电压或功率 |
| 其他 | capacity=112、reserved=0；明确拒绝其他版本、采样配置或非法载荷 |

FCR1 前 66 个流样本按旧 FPGA 暂态约定丢弃。CRC 或帧头错误会丢弃并寻找后续有效帧。
序号和索引按 uint32 检查；epoch、索引回绕、频率配置变化或索引间断会切分连续段并
复位滤波/解调，清空音频积压。削顶窗口输出“未知”并静音。
FPGA 累计丢样不能单独认定为本次窗口丢样；重连前后的计数含义应分别看待。
超过 0.6 秒无有效 I/Q 帧会清理活动显示和音频，显示等待/搜索/断流；USB 错误会记录并停止
接收，可手动重新开始。文件回放结束则保留最后画面，不伪造后续数据。

## 算法与实时边界

采用 NumPy/SciPy。每约 20 ms 连续 I/Q 计算包络变化、相邻相位差及谱集中度，
输出 AM/FM/未知/无有效信号；支持模式需连续三个窗口确认。特征评分不是经过标定的概率。
低调制度、严重噪声、复合调制或多个载波可能判为未知；现阶段不能保证所有输入正确分类。

- 载频：使用帧内 phase_step 换算实际 LO（87 MHz + phase_step×43.5 MHz/2³²），
  加基带残余偏移；不是直接照抄帧 RF 字段。正 alias 与射频预选仍是前提。
- AM：包络解调，连续 50 ms 时间常数估计基准幅度，去直流；调制度由平滑包络的
  1%/99% 分位数估计，仅适用于具有载波的普通 AM，非校准峰值仪表。
- FM：相邻 I/Q 相位差解调；频偏由瞬时频率分位数估计；载频采用对称分位中心，
  非对称消息会影响中心估计。调制指数仅在检测到明显单音时给出，不能将语音强制当作单音。
- 音频：161 tap FIR 低通 15 kHz → /5 → 有状态 12/25 重采样到 48 kHz → 35 Hz
  高通；使用 SciPy FIR/滤波函数并保留块间状态。模式切换、间断和重新开始后静音首 20 ms。
  FM 为单声道解调，未实现立体声/RDS。输出限幅到 ±0.95；WAV 不带扬声器音量系数。

采集线程接收字节并发送后台命令，有界接收队列 128 项（每次 USB 读最多 32 KiB，数据容量上限约 4 MiB）。
队列满时丢弃当前读取块并计数字节，后续序号/索引检查暴露间断；不阻塞等待绘图。
处理线程完成解码、DSP 和 FFT；Qt 每 50 ms 获取最新显示快照，只绘制当前视图，
GUI 事件不逐帧排队。设备查询、保存和记录扫描均有独立后台任务。
两模式控制在独立后台线程运行；命令队列16项，ACK事件队列128项，
质量分析最多保留96个I/Q帧。采集读与命令写分别在后台执行，不在GUI线程等待ACK。
音频缓存上限 250 ms，溢出丢弃最旧块并计数；开始/复位后预缓冲至少 40 ms，
此阶段静音并单独记录样本数，实际欠载再计数和重新预缓冲，不循环播放旧音频。

TRI1满帧I/Q吞吐约2.306MB/s，25%余量约2.883MB/s；ACK及USB总线开销另计。
上述缓存设置是软件默认值；实际持续 USB、操作系统调度、时延和端到端音质仍需实测。

## 验证

```powershell
& 'D:\conda_envs\ads807_host\python.exe' -B -m pytest tests/ads807 -q -p no:cacheprovider --basetemp .harness/ads807_host/pytest
& 'D:\conda_envs\ads807_host\python.exe' -B -m ads807.verify --output .harness/ads807_host/verification
```

第二条命令默认离屏、无 USB、无物理音频，保存四种合成场景的结果、真实界面截图和
AM/FM 连续捕获。可选 `--audio-device N` 进行约 1.2 秒的低音量 1 kHz 合成 AM 解调输出，
设备编号以本机枚举结果为准，不能跨机器复用。

本工程独立验证无需外层harness。外层项目仍保留集成任务，以下命令仅从外层项目根目录运行：

```powershell
& 'D:\conda_envs\ads807_host\python.exe' -B -m harness.runner run --jobs 3 --task ads807-host-offline-verification
```

`tasks.proposal.json` 保留外层harness的任务定义备份；它使用外层根目录相对路径，
不是独立host工程的运行器。独立运行直接使用本节前两条命令。

本轮验证证据及限制见 `VALIDATION.md`。离线测试通过不等于 ADS807 模拟接口、FPGA
时序、上板连续接收或射频系统验收通过。
