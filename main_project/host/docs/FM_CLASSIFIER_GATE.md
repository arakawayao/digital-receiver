# 部分广播频道被判未知

2026-10-26。用户手动调谐：103.7/91.4/89.9/101.7 MHz 可听清，
93.4/105.7/90.9/98.1 MHz 等显示未知；手机可正常接收。

## 实际原因

`D:/class_project/main_project/capture_20261026_181810_278439` 是 93.4 MHz 实际采集。
保存时 USB、FPGA/主机丢样、CRC、序号、削顶和本次音频欠载/溢出计数全部为零。
I/Q 连续 0.884 秒，原解调音频全零。按 40 ms 分块检查 22 块：

- 包络变异系数 0.128–0.163，超过窄带 FM 的 0.12 门限。
- 相邻样本相位相干度 0.916–0.970。
- 频谱集中度 0.306–0.787，百分位频偏约 31.8–70.8 kHz。
- 22 块均通过现有宽带 FM 资格条件，但最终分类仍强制要求包络系数小于 0.12，
  全部返回未知，继而按原设计输出静音。

第一轮 r3 修改 `dsp.analyse` 的最终 FM 分支，使已通过宽带 FM 检查的结果保持 FM。
未提高既有宽带门限、未强制将未知输入判为 FM；保留 AM、低频偏 FM、
削顶、弱信号、纯载波与噪声的检查。不修改 FPGA、调谐频率、USB 或音频格式。

## 验证与边界

合成回归覆盖带包络起伏的宽带 FM、削顶拒绝，以及多种带宽的滤波复噪声。
RF 参数覆盖 88/93.4/98.1/105.7/108 MHz；这是相同基带的分类回归，不是射频全频段验收。
实测 I/Q 离线复算及恢复音频在 `evidence/fm_classifier_20261026/`。
修复后 93.4 MHz 的 22/22 块均为 FM，既有三份 103.7 MHz 数据的 99/100/100 块仍全部 FM。
实际 `transport.fcr` 通过生产文件回放链路处理 984,025 点，识别 FM、非零音频、CRC=0、无处理错误。
完整上位机回归 152 项通过。以上仍不包含重新连接天线后的实机放音验证。
后续三份实采的分析见下节；实机重启后的听感仍需用户确认。

## 三个新增频道的逐份复核（r4）

输入均为 43.5 MS/s ADC、500 kIQ/s、I+jQ signed16/32768，手动载频。
三份元数据中 CRC、帧头、间断、FPGA/主机丢样、削顶、音频欠载/溢出均为零。
保存发生在停止后，不能把保存时的 last_valid_age 当成运行中断流。

### 105.7 MHz

`capture_20261026_183124_208967`，2.972 秒。包络系数约 0.183–0.217，
超过原宽带路径的 0.18 门限；但每个 40 ms 块的鉴频频谱都有约 19.005 kHz 峰，
高于邻近噪声底约 13.5–20.9 dB，符合广播立体声导频特征。

r4 增加导频辅助的 FM 资格通道：包络系数 <0.28、相位相干度 >=0.8、
频谱集中度 >=0.15、频偏通过原相位噪声条件，并且 19 kHz ±50 Hz 范围内
谱峰高于邻域中位功率 16 倍且占总功率 >0.2%。这些是软件启发式条件，
不是校准的射频性能指标。不改变原单声道 FM 判据，也不要求所有 FM 都带导频。

修复后 74/74 块为 FM；生产 transport.fcr 回放处理 983,808 点，输出非零音频，
CRC/间断为零。恢复的 16 位 WAV 为 `evidence/fm_classifier_20261026/1057MHz_recovered.wav`。
尚未确认新版实机听感。

### 90.9 MHz

`capture_20261026_183146_097221`，1.205 秒。原保存结果已经为 FM，原音频也非全零。
独立逐块检查是 29 FM、1 AM；那一个低瞬时频偏窗口会触发 AM 判据，仍有偶发分类风险。
生产回放最终为 FM、音频非零，CRC/间断为零。
用户随后确认仍断断续续。r5 修复了确认状态与解调状态不一致的问题：
此前已确认 FM 后，单次候选 AM 在等待三次确认期间却立即变为“未知”，
触发静音并重置滤波器；恢复 FM 又有 20 ms 的滤波预热静音。
现在切换到另一种有效调制需连续三次确认，等待期间保持已确认的解调滤波状态，
reason 显示候选类型与进度、置信度为零且不报旧参数，stats.classification 记录保持次数。
未知、无信号、削顶仍立即静音，间断/换代清除确认状态；持续 AM 可正常切换。

在同一 1.2 秒 NPZ 的每个 40 ms 块都分析的可重复对照中，约 0.44 秒处的单次 AM 候选
原来造成 40 ms 静音加 20 ms 重启预热，r5 消除了这 60 ms 中断。
音频零值比例由 13.33% 降至 8.33%，后者全为最初的识别确认与预热。
实时分析有 0.1 秒限速，实际触发位置与时长会受调度影响；不能以离线改善声称全部断续已解决。
证据在 `continuity_r5.json`，恢复试听为 `909MHz_continuity_r5.wav`，均位于同一 evidence 目录。

### 98.1 MHz

`capture_20261026_183159_811496`，2.088 秒。平均 I/Q 电平约 -38.9 dBFS，
低于同批 105.7 的 -32.6 dBFS、90.9 的 -30.4 dBFS；这些不是 SNR 或 ADC 输入电压。
包络系数约 0.215–0.238、相位相干度约 0.725–0.752，没有稳定的 19 kHz 窄峰。
52/52 块仍为未知，生产回放也为未知、全零音频。无导频不能排除单声道 FM，
现有数据不足以确定是低信噪比、干扰、前端非线性还是分类器局限。

另外仅在离线诊断中试验 60/80/100/120/150 kHz 基带低通，仍全部为未知，
没有将这些额外滤波加入应用。导出的 `981MHz_diagnostic_forced_fm.wav` 使用 50 us
去加重和强制 FM 鉴频，专供听辨，不用于自动识别或接收成功证明。
用户反馈诊断文件“什么都没有”，未确认听到节目；目前暂不能做信号源对照。
下一步有条件时对照真实 FM 收音机，以及相同接线下 98.1 MHz 信号源输入；
必要时对照 LNA 降增益/旁路。不能仅因未报告 ADC 削顶而排除模拟过载或互调。

完整上位机回归 157 项通过（含新增导频、邻近频率、AM 和削顶拒绝用例）。
随后 r5 完整回归为 162 项通过，新增覆盖双向有效调制瞬态、持续切换、无信号/未知立即退出、
间断后重新确认；r5 已重新完成三份 transport 文件回放，均无 CRC/间断或处理错误。
三份旧 103.7 MHz 数据仍为 99/100/100 块全部 FM；93.4 MHz 仍为 22/22 FM。
结构化证据为 `evidence/fm_classifier_20261026/latest_reanalysis.json`。
