旧进程音频计数跨采集累计；例如 1816 欠载、999 溢出不能写成本次 48 秒内的次数。

## 音频长时间播放修正（2026-10-27）

用户实测日志显示仅音频欠载/溢出增长，USB CRC、I/Q 连续性和 DSP 丢弃没有增长。
这将问题范围收敛到输出设备回调调度和音频有界队列，不归因于 RF 或 USB。

Windows 默认 MME 设备实测回调可能约每 40 ms 成批到达，虽然程序按 20 ms 请求 960 点；
旧 120 ms 预缓冲和 250 ms 容量遇到长时间调度抖动时可能先回调空窗欠载，再在处理线程追赶时溢出。
新版默认设备选择优先使用与系统默认输出同名且支持 48 kHz 的 Windows WASAPI，
打开失败才回退系统默认设备；用户在设备下拉框中明确选择的设备不自动替换。
队列会按实际设备 latency 配置预缓冲 `max(120 ms, latency+80 ms)`，容量为预缓冲加
`max(250 ms, latency+120 ms)`；仍是有界队列，不伪造样本。

日志新增实际设备、Host API、延迟、预缓冲/容量，以及交付最大间隔、回调最大间隔、
回调耗时、丢弃点数、欠缺点数和清空原因。保存的 integrity.stats.audio_diagnostics 同样保留这些字段。
因此后续长测可区分设备回调批处理、DSP 交付停顿、分类切换清空与真实输出欠载。

## 原有软件修改

- 音频预缓冲曾从 40 ms 改为 120 ms；当前按输出设备延迟动态配置，容量保持有界。
  40 ms 原门限只有一个 DSP 批次，容易受调度抖动影响。真实断流仍计欠载，未补造音频。
- 每次采集开始重置音频计数；数据间断清缓存时仍保留本次计数。
- 元数据记录预缓冲、计数范围、扬声器启用状态与设备回调原始状态。
- 异常时限频记录欠载、溢出、设备状态、剩余缓冲和队列/回调诊断；GUI 不执行 USB/音频阻塞操作。
- 不修改 FPGA、射频链路、分类门限或解调音频频率响应。

针对确定性 60 ms 音频交付停顿，动态缓冲压力测试无欠载/溢出；
测试同时检查真实长断流仍触发欠载和重新预缓冲。完整上位机回归需以当前测试结果为准；
离线通过不代表实机播放已修复。
