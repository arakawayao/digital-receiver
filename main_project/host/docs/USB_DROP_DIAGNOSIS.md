# USB 主机丢弃诊断

2026-10-25，实测链路为天线 → 88--108 MHz 滤波器 → 约 46 dB LNA（80 kHz--2 GHz）→ ADC。
手动调谐 103.7 MHz 可以收到并播放 FM，但播放断续。日志示例中 CRC、帧头和全局序号均为零错误，
而“主机丢弃字节”按 32 KiB 批次持续增长。

这组计数说明 FPGA 已生成合法 TRI1 帧，丢弃发生在主机接收后的有界队列，而不是 CRC 或 FPGA 全局序号校验。
丢弃会切断 I/Q 连续段，FM 相位鉴别器会重置，表现为音频断续；LNA 本身不改变 USB 字节率，
但强信号仍需继续观察削顶和 I/Q 电平。

本轮修改：

- DSP 批处理门限改为 20,000 I/Q 样本，减少小块调度与 Python/NumPy 拼接开销；
- DSP 有界批队列从 256 扩为 512 批，约可缓冲 4.6 秒的 32 KiB 数据；
- 界面完整性面板新增“DSP 丢弃样本”，用于区分接收入口和 DSP 队列压力；
- `runtime.stats()` 增加来源字段，保存记录保留 `source_queue_dropped_bytes`、`dsp_queue_dropped_bytes` 和 `dsp_dropped_samples`。

验证：129 项测试和四种离线场景通过；未连接真实 LNA/ADC，不能把离线通过等同于持续 USB 零丢样。

重启后用手动 103.7 MHz 运行 20--30 秒，观察：

1. `主机丢弃字节` 是否保持 0；
2. `DSP 丢弃样本` 是否保持 0；
3. `I/Q 连续性异常` 和 `本次缺失样本` 是否保持 0；
4. `音频欠载 / 溢出` 是否增长。

如果仅 `DSP 丢弃样本` 增长，仍是主机处理速度不足，需要保存 `metadata.json` 中的
`processing_timing`、`dsp_queue_depth` 和丢弃来源继续定位；如果 `削顶帧` 增长，应先降低 LNA 增益或增加前端衰减，
不能用软件静音掩盖 ADC 过载。
